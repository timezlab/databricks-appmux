# Architecture

One-page map of what exists and what is planned. Rationale lives in the ADRs
linked from [docs/index.md](docs/index.md#decisions-adrs--append-only); behavior
is described in [docs/product/v1-design.md](docs/product/v1-design.md).

**Shape — part of the code exists.** Module names below come from
[v1-design §3.4](docs/product/v1-design.md#34-module-boundaries); the
[plan](specs/001-appmux-v1/plan.md#source-code-repository-root) fixes the paths
(`src/appmux/<module>/`, `web/`, `tests/`, root `app.yaml`) and
`tests/unit/test_module_boundaries.py` enforces the import rules. A row is ✅ only
when its tests pass. Container runs so far, all on the dev App on Free Edition (one workspace): a hand-driven deploy on
2026-10-31 (the registry loaded, the canary ran, `self_check` passed its 13 checks); integration tests
from the dev machine through the real Apps proxy (from 2026-10-31, the credential modes and the UI
pages among them); and tests inside the container (2026-11-05, `scripts/run-container-tests.sh`).
Every container-only test file has run at least once; what still has no container result is named
in each row and in [tech-debt](docs/tech-debt.md).

**Legend:** ✅ implemented · 🟡 partly implemented (the Purpose cell says which part) · 🔜 planned

## Child app lifecycle

```
register → Update (snapshot) → check requirements → build env → start (sandbox) → health check → swap route
```

A route opens or swaps only as the last step, after the health check passes. A
failure at any earlier step leaves the route table and the running release
untouched; rollback activates a stored release with no source read
([ADR 0005](docs/decisions/0005-run-releases-from-immutable-snapshots-and-swap-after-health.md)).

## Key boundaries

- **Route opening is health-gated** — only the `reconciler` opens or closes a
  route, and only after a passing health check (constitution II).
- **Child apps stay unmodified** — a child's `app.yaml` and source are inputs;
  appmux-only settings live in the registry (constitution I,
  [ADR 0008](docs/decisions/0008-follow-the-standalone-app-yaml-contract.md)).
- **Updates are non-disruptive** — the new release starts beside the old one;
  changing one child never interrupts the others (constitution III).
- **Pure modules** — `authz` and `routing` do no I/O; `routing` and `authz` are
  tested as tables.
- **Every child starts in the sandbox** — no other code path execs a child, and
  no route opens while `self_check()` fails.
- **Platform data is written by a person** — `apps` and `platform_settings` are
  written with the platform admin's own OBO identity, never the shared SP
  ([ADR 0004](docs/decisions/0004-keep-decisions-in-a-nine-table-lakebase-registry-with-split-writers.md)).
- **A request grants nothing** — `authz` and the `reconciler` read `apps`, not
  `permission_requests` ([ADR 0011](docs/decisions/0011-gate-credentials-and-platform-fields-behind-a-request-catalogue.md)).

## Platform constraints

appmux runs inside one Databricks App container with no root and no cgroups, so
its shape follows what the platform allows: children are isolated by
unprivileged namespaces, CPU and memory limits are best-effort, and the proxy in
front speaks HTTP/1.1 with a 300 s ceiling. The measured facts are in
[Platform at a glance](docs/reference/databricks-apps-platform.md#platform-at-a-glance)
(Free Edition only; a paid workspace may differ,
[TD-005](docs/tech-debt.md#td-005-platform-measurements-come-from-free-edition-only)).
